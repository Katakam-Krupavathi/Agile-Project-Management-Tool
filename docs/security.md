# Security Architecture & Honest Limitations

## Implemented Controls

- **Password Storage & Constant-Time Login**: Argon2id hashing via `argon2-cffi` (`PasswordHasher` defaults). Plaintext passwords are never logged or returned in responses. When `authenticate_user` looks up an unknown email, it still runs a dummy Argon2 verification (`verify_dummy_password`) so response latency matches the existing-user path and prevents timing-based account enumeration.
- **Session Cookies & Server-Side Revocation (`token_version`)**: Signed, time-limited tokens (`itsdangerous.URLSafeTimedSerializer`) embed both the user ID (`uid`) and the user's integer `token_version` (`tv`). Cookies use `httpOnly` and `SameSite=Lax`, and `SESSION_COOKIE_SECURE` defaults to `true` when `APP_ENV=production`. Calling `POST /api/v1/auth/logout` atomically increments `users.token_version` in SQLite, immediately invalidating any previously issued session cookies (including replayed cookies and active SSE streams, which re-validate `token_version` on every poll).
- **CSRF Protection**: Double-submit cookie pattern (`agile_pm_csrf` cookie matched against `X-CSRF-Token` header via constant-time `hmac.compare_digest`) enforced on every mutating endpoint (`POST`, `PATCH`, `DELETE`).
- **Multi-Layer Brute-Force & Enumeration Defense**:
  - **Per-(IP, email) login limiter**: `5` failed attempts per `60s` (`LOGIN_RATE_LIMIT_MAX_ATTEMPTS` / `LOGIN_RATE_LIMIT_WINDOW_SECONDS`) → `429 Too Many Requests` with `Retry-After`.
  - **Per-IP login limiter across all emails**: `15` failed attempts per `60s` (`LOGIN_IP_RATE_LIMIT_MAX_ATTEMPTS`) blocks credential-stuffing / password-spraying across distinct accounts from a single IP.
  - **Per-account progressive soft delay**: Consecutive failures against an email across any IP apply an exponential backoff delay (`LOGIN_ACCOUNT_BACKOFF_BASE_SECONDS=0.05` up to `LOGIN_ACCOUNT_BACKOFF_MAX_SECONDS=1.0` over `300s`) instead of a hard account lock, preventing an attacker from locking a legitimate user out from their own IP.
  - **Registration rate limiter & `409` tradeoff**: `POST /api/v1/auth/register` is rate-limited per IP (`10` attempts per `60s` via `REGISTER_RATE_LIMIT_MAX_ATTEMPTS`) and runs dummy Argon2 verification on duplicate emails so timing matches. **Tradeoff:** Registration keeps an explicit `409 Conflict` (`EMAIL_ALREADY_REGISTERED`) for clear self-serve UX and API client semantics rather than returning a silent `201` (which requires out-of-band email verification to inform existing users); bulk enumeration is mitigated by the per-IP registration rate limiter and matched Argon2 work.
- **Reverse-Proxy Client IP Forwarding**: The API container runs Uvicorn with `--proxy-headers` and `--forwarded-allow-ips "${FORWARDED_ALLOW_IPS}"` so rate limiters and audit logs use the real client IP forwarded by Nginx rather than the internal container IP.
- **Production Startup Guards & Gated Docs**: When `APP_ENV=production`, `Settings` refuses to boot if `SECRET_KEY` is a default placeholder or shorter than 32 characters, defaults `SESSION_COOKIE_SECURE=true`, and disables `/docs`, `/redoc`, and `/openapi.json` (`ENABLE_API_DOCS=false` by default in production). `docker-compose.yml` requires `SECRET_KEY` via `.env` and defaults `SEED_DEMO=false`.
- **Authorization & Anti-Enumeration**: Centralized `require_project_role` / `require_story_role` / `require_task_role` dependencies on every scoped route. Non-members receive `404` instead of `403` to avoid leaking resource existence. Last-owner removal and demotion are blocked (`409`).
- **Input Validation & Payload Limits**: Pydantic v2 schemas enforce field types, regex patterns (`^[A-Z]{2,5}$` project keys), and strict max lengths on all inputs. `RequestSizeLimitMiddleware` rejects bodies exceeding `MAX_REQUEST_BODY_BYTES` (default `1 MB`) with `413` in RFC 7807 format.
- **HTTP Security Headers (API & Nginx SPA) & CORS**: `SecurityHeadersMiddleware` sets `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, and `Content-Security-Policy` on API routes. `frontend/nginx.conf` adds `Strict-Transport-Security` (HSTS) and a strict SPA `Content-Security-Policy`. CORS uses an explicit `CORS_ORIGINS` allow-list.
- **Secrets & Dependency Auditing**: Secrets are loaded strictly via environment variables (`.env` gitignored). CI runs `pip-audit` and `npm audit --audit-level=high` on every push.

## Honest Limitations

1. **SQLite Single-Writer Ceiling**: SQLite WAL supports concurrent readers, but only one writer at a time (`BEGIN IMMEDIATE` + `busy_timeout=5000` serializes writes). Under heavy multi-instance load, write contention would require moving to PostgreSQL.
2. **In-Memory Rate Limiter & SSE Stream Counter**: Rate limiters and per-user SSE stream counts are stored in process memory; restarting the API resets counters, and multi-replica deployments would require a shared store (e.g., Redis).
3. **No Email Verification or Password Reset**: Registration activates accounts immediately and `ConsoleMailer` logs emails to stdout rather than delivering via SMTP/SES.
4. **No MFA or SSO/OAuth**: Authentication is password-only; production deployments for larger organizations should add TOTP MFA and OIDC/SAML SSO.
5. **Per-User (Coarse) Session Revocation**: Incrementing `users.token_version` on logout revokes all active sessions for that user rather than tracking per-device session rows individually.
